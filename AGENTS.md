# AGENTS.md

Здесь только правила работы с кодом.

## Код

KISS и YAGNI важнее DRY и SOLID. SSOT — крайний приоритет: ни производных полей,
ни вторых источников правды на всякий случай.

- Не добавляй фоллбеки, страховочные проверки и абстракции без требования.
  Явная ошибка лучше молчаливого восстановления.
- Проверяй данные на входной границе, не дублируй проверку внутри.
- Не пиши обёртку тоньше того, что она оборачивает. Хелпер сначала ищется
  готовым пакетом.
- Комментариев нет: непонятный код переписывается, а не объясняется. Объяснения
  живут в коммитах и карточках.
- Расхождение конвенций между файлами — повод спросить, а не выбрать любой.
- Код целиком на английском, включая тесты, сообщения ошибок и commit messages.
  Русский — в md, карточках и диалоге.
- Тесты — на отказы, которые молчат: не видны в UI, не роняют проект, всплывают
  счётом или порчей данных. Видимое глазами не покрывай.

## Границы слоёв

Разделяй код по причинам изменения, а не по числу строк. Файл делится, когда в
нём появляются две независимые обязанности; большой связный алгоритм сам по себе
не является god-файлом.

- Controller и React-компонент принимают данные, делегируют работу и формируют
  представление. В них нет обхода сайтов, SQL, векторных вычислений и доменных
  формул.
- Workflow координирует этапы сценария, но не знает Prisma, HTTP-клиентов и
  деталей SDK. Вычислительный сервис не управляет очередями и хранением.
- Repository — единственная граница Prisma и БД. ORM-типы не выходят в workflow
  и UI; преобразование persistence-моделей выполняется на этой границе.
- Клиент внешней системы только вызывает её API и переводит её ошибки в ошибку
  своей границы. Разбор и доменная обработка результата принадлежат отдельному
  сервису.
- Processor очереди распаковывает job, вызывает workflow и ставит следующий job.
  Бизнес-правила в processor не добавляются.
- На frontend contract валидирует сетевую границу, model считает производные
  данные, UI отображает их. Компонент не повторяет формулы model.
- Не создавай файл ради одной константы, типа или однострочной обёртки. Такие
  элементы размещаются рядом с владельцем протокола либо в уже существующем
  связном файле типов.
- Не разделяй код косметически: после выноса слой не должен импортировать детали
  слоя, от которого его пытались отделить.
