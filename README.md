# SEO AI Analyzer

Несколько версий одного инструмента живут рядом, чтобы их можно было сравнить
на одних и тех же данных:

| Версия | Что это                                         |
| ------ | ----------------------------------------------- |
| `v1`   | первая попытка: работа с конкретными статьями   |
| `v2`   | обход сайта и сравнение двух доменов по запросу |
| `v3`   | сравнение конкретных страниц по списку адресов  |
| `v4`   | чужой репозиторий (GIST Map), развёрнутый рядом |
| `v5`   | сопоставление абзацев с конкурентами            |

Версии намеренно не делят код. Дублирование между ними — условие эксперимента:
правка ради одной не должна незаметно менять другую.

`v4` — не наш код, а репозиторий стороннего исполнителя (`Bartlby1987/GIST`),
поэтому у него свой `package.json`/`package-lock.json` и он не входит в
npm-воркспейсы монорепы (`apps/*/*` его не подхватывает).

## Разработка

Нужны Node.js 24 или новее, PostgreSQL и Redis на хосте, и любой
OpenAI-совместимый endpoint для embeddings. К провайдеру ничего не привязано:
в проде это внешний шлюз, а `.env.example` каждой версии смотрит на локальную
Ollama, потому что ей не нужен ключ.

```bash
npm install
createdb seo_v1 && createdb seo_v2 && createdb seo_v3
cp apps/v1/api/.env.example apps/v1/api/.env
cp apps/v2/api/.env.example apps/v2/api/.env
cp apps/v3/api/.env.example apps/v3/api/.env
npm run db:migrate -w @seo/v1-api
npm run db:migrate -w @seo/v2-api
npm run db:migrate -w @seo/v3-api
npm run dev:v1   # или dev:v2 / dev:v3, можно все сразу
```

`v4` — отдельное дерево зависимостей, ставится один раз своим `npm install`:

```bash
npm install --prefix apps/v4
npm run model:fetch --prefix apps/v4   # эмбеддинги, кладёт .models рядом с приложением
npm run dev:v4
```

`v5` — обычный воркспейс, но ему тоже нужна модель:

```bash
npm run model:fetch -w @seo/v5-api
npm run dev:v5
```

Версии разведены по портам и хранилищам, поэтому запускаются одновременно:

| Версия | API    | Web    | База PostgreSQL | База Redis |
| ------ | ------ | ------ | --------------- | ---------- |
| `v1`   | `3001` | `5173` | `seo_v1`        | `2`        |
| `v2`   | `3002` | `5174` | `seo_v2`        | `3`        |
| `v3`   | `3003` | `5175` | `seo_v3`        | `4`        |
| `v4`   | `3004` | `3004` | —               | —          |
| `v5`   | `3005` | `5177` | —               | —          |

У `v4` один процесс на оба: сервер Next.js отдаёт страницу и API на одном порту.
`v4` и `v5` считают эмбеддинги локальной моделью `multilingual-e5-small`
(transformers.js), поэтому им не нужны ни PostgreSQL, ни Redis, ни ключ
внешнего провайдера.

PostgreSQL хранит анализы, страницы, фрагменты, векторы и оценки. Redis нужен
только BullMQ. У каждой версии свой сгенерированный Prisma-клиент внутри её
`node_modules` — общий на монорепу клиент версии перетирали бы друг у друга.

`LLM_BASE_URL`, `LLM_API_KEY` и `LLM_EMBEDDING_MODEL` выбирают провайдера
embeddings. Запрос и фрагменты уходят простым текстом, без префиксов задач под
конкретное семейство моделей, поэтому подходит любая модель.

Ответы провайдера не считаются доверенными: `EmbeddingsService` раскладывает
векторы по индексам и отвергает партию, где индексы повторяются или где разные
тексты получили один и тот же вектор.

## Структура

```text
apps/landing                оглавление поддомена и его robots.txt
apps/v1/{api,web,examples}  первая версия
apps/v2/{api,web}           версия с обходом
apps/v3/{api,web,gist}      версия по конкретным ссылкам, gist — сервис отбора на Python
apps/v4                     чужой репозиторий (GIST Map), свой package.json
apps/v5/{api,web,examples}  встраиваемый анализатор абзацев
infra                       прод-компоуз и скрипты деплоя
docs                        справочные материалы
```

## Прод

[`infra/deploy.sh`](infra/deploy.sh) собирает образы и поднимает рабочий набор:
traefik, лендинг, `v4` и `v5`. Из `.env` ему нужен только `APP_DOMAIN` —
базы и ключи провайдера этим версиям не нужны, модель уезжает внутрь образа на
этапе сборки.

Версии `v1`–`v3` вынесены в профиль `legacy` и по умолчанию не поднимаются:
на VPS с 2 ГБ памяти они занимали место, а сравнивать по ним уже нечего.
Когда они снова понадобятся, нужен хост с PostgreSQL и Redis
([`infra/host-setup.sh`](infra/host-setup.sh)), заполненный `.env` и запуск
профилем:

```bash
docker compose --profile legacy up -d
```
